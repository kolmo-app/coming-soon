# KOLMO 운영런북 (Operations Runbook)

**버전** v0.2 · **상위문서** 00-magna-carta.md · **범위** 운영감시, 롤백, 장애·비상대응, 기록 보존

## 1. 운영감시

배포 후에도 다음을 KVU로 기록한다.

- 검출 결과(Confirmed / Reclassified / False signal)와 리드타임 분포
- 거짓경보율 (오경보 예산 대비 소진률)
- 누락(거짓음성) — 사후 리뷰에서 발견된 미검출 전환
- 탐지·전달 지연 (게임시계 vs 벽시계, 피드 레이턴시 분리 기록)
- 사용자 개입 (음소거, 무시, 이의제기)
- 파이프라인 장애와 데이터 계보 단절

**쌍 지표 원칙**: 리드타임은 반드시 동일 기간 정밀도(오검출률)와 함께 보고한다. 어느 한쪽만의 개선 보고는 무효다.

## 2. 자동 롤백 트리거

다음 중 하나 충족 시 마지막 검증상태로 자동 복귀한다.

1. 등록된 안전제약 위반
2. 데이터 계보 단절 (`integrity=FAIL`)
3. 정책 드리프트 — 배포본이 등록된 정책버전과 불일치
4. 등록된 롤백 임계값 충족 (오경보 예산 소진, 보정 붕괴 등)

롤백 절차: 트리거 KVU 기록 → 마지막 검증상태 복귀 → 권한자 통보 → 사후 리뷰 등록(G0). **롤백은 실패의 은폐가 아니라 정상적인 전환과정이다.**

## 3. 장애·비상대응

- 비상조치는 만료시점을 가진다. 정식 승인 없이 영구화될 수 없다 (대헌장 제6조 3항).
- AI가 위기를 근거로 자신의 권한 확대, 로그·감사·롤백 제거를 제안하면 자동 기각한다 (제5조 4항).
- 센서 접근 실패(지역 차단, 타임아웃 등)는 `○obs`로 기록하며 부재(`∅`)로 승격하지 않는다. VPN·위치 우회로 재시도하지 않는다.

## 4. 기록 보존과 공개

1. 과거 데이터·모델·프롬프트·정책버전·실패기록은 소급 수정하지 않는다.
2. 성과뿐 아니라 실패와 반례도 제품 신뢰도의 일부로 공개한다 (관측 기록부의 Reclassified/False signal 공개 원칙).
3. 검증 무기한 연장으로 현 체계를 유지하려는 시도는 **현상유지 포획**으로 명시 기록한다.
4. 보존 대상 연결 데이터: `관측 KVU → 당시 추론 → 발동된 전환 → 채택된 모델 → 실제 결과 → 실패·롤백`. 이 연쇄가 KOLMO의 축적 자산이며, 어떤 단계에서도 사슬을 끊는 삭제·수정은 금지된다.

## 5. 초기 단계 운영 (1인 다역)

한 사람이 여러 역할을 겸하는 동안에도:

- 승인 행위는 역할별 별도 키·별도 커밋으로 기록한다.
- "제안(AI) → 검증 → 배포 승인 → 감사 기록"의 4단계를 하나의 행위로 합치지 않는다.
- 역할 겸임 사실 자체를 KVU `authority` 필드에 명시한다.
